# Feature 001：finfreedom 能力迁移为 DSH 插件

**状态：** 实施中；DSH 工作台界面需求已补充
**日期：** 2026-10-29
**优先级：** P0
**来源：** `financial-freedom/app/platform_mcp.py`、`platform_mcp_server.py`、`ai_tools.py`、`agent_extensions.py`、数据源适配器及对应文档。详细枚举见 [能力盘点](capability-inventory.md)。

## 背景与用户价值

Financial Freedom 的 Agent 核心依赖 DeerFlow，稳定性和可维护性不符合当前需求。用户要在 DSH 的已配置运行 profile 中使用 finfreedom 的市场、投研和个人数据工具，并继续使用 finfreedom MCP 与 Skills；DSH Web 中还需提供与原项目工作台基本相似的页面。新仓库不依赖旧 Web 进程或自研 Agent 主循环。

## 范围

### 必须交付

- 可安装的 DSH bundle，安装后在指定 profile 自动挂载 finfreedom 工具与随包 Skills；提供对现有 web、tui、headless 等 profile 的批量安装命令与验证结果。新 profile 创建后可重复运行安装命令。
- 独立的 finfreedom 核心服务及标准 MCP server，提供原有 `catalog`、`read`、`research`、`prepare_holdings_import`、`write` 五类入口；DSH 工具名保持 `mcp__finfreedom__*` 或提供有版本的显式映射，不发生静默重命名。
- 36 个可读资源、25 个现有可公开调用的研究工具、5 类受限写入和持仓草稿工作流的行为等价迁移。既有 `get_account_snapshot` 不在公开 `research` 目录中，保持禁用，除非单独建立可信的本轮授权机制。
- 各数据源的采集、缓存、错误和来源时点逻辑能在新仓库独立运行；新安装从空库开始，尚无历史数据时明确返回未配置或无数据。
- finfreedom 业务存储默认连接本地 SQLite；工作台的 finfreedom 数据库设置可改为连接用户自建或 Docker 启动的 MySQL 兼容数据库。DSH 对话可根据不含密钥的连接信息引导并准备配置，工作台安全表单完成凭据录入、测试和启用。两种入口复用同一连接校验与切换流程。
- DSH Web 安装后提供 finfreedom 可见导航与工作台页面。高频入口位于新会话下方，原项目的更多工具按类别放入导航；页面继承 DSH 的会话布局与主题，覆盖原项目主要工作台页面及其适用的业务流程。
- 内置 finfreedom 研究 Skills，保留 Skill 元数据、名称、参考文件和按需加载语义；用户后续安装 Skill 使用 DSH 的扩展机制。旧私有 Skill 内容不导入。
- 通过 DSH 挂载第三方 MCP 的能力；凭据只在本机私有配置存放，写权限逐连接显式启用。旧私有 MCP 配置不导入。
- 提供本机安装与 Docker Compose 部署、升级、卸载、备份、回滚和故障诊断文档，以及与能力盘点逐项对应的自动化契约测试。

### 不在范围

- 原 Financial Freedom 的独立 Web 进程、移动端、小程序、DeerFlow worker、自研模型对话循环和旧 `app.main` 路由。原工作台页面及其适用业务能力迁入 DSH 界面，数据库设置位于 DSH 工作台中。
- 新增交易执行能力或扩张原 MCP 写权限；不实现券商真实交易授权流程。
- 不恢复旧网页里的 AI 模拟盘自动研究并生成模拟委托任务；本期只读保留其账户、委托和历史任务查询。未来若要迁移该流程，需单独设计 DSH Agent 可调用的模拟委托工具、额度/风控与停止机制。
- 把公共网页数据源宣称为具有实时或商业再分发 SLA 的正式行情接口。
- 迁移旧用户数据、旧私有 Skill/MCP 配置或旧凭据；新安装不自动恢复个人持仓、历史研究或富途连接。

## 用户故事与验收场景

### US1：一次安装后，DSH 可发现 finfreedom（P0）

用户对一个或全部现有 profile 安装插件并重启/热加载对应 DSH 进程后，工具列表显示五个 finfreedom MCP 入口，Skill 列表显示随包 Skill，`catalog` 能返回完整目录。

**验收：** 干净 DSH profile 安装无手改核心代码；`dsh --profile <name> --dump-config` 出现插件层；实际启动后能调用 `catalog`。安装重复执行不产生重复实例或工具名冲突；卸载后工具消失而用户数据保留。

### US2：在 DSH 查询和获取市场信息（P0）

用户可以搜索标的，查询 A 股/港股/美股/基金/黄金、指数、交易日历、行情、日线、新闻、央行流动性、板块和资金数据，并调用研究工具进行确定性统计与基金披露采集。

**验收：** `capability-inventory.md` 中所有市场类资源与研究工具逐项通过等价契约测试；返回来源、时间、币种/单位、覆盖、新鲜度或明确缺口；列表有上限和分页；上游故障不把旧数据标为实时。

### US3：读取和研究个人资料（P0）

用户可在可信绑定的 owner 范围内读取持仓、文档、研究记录、投资记忆、工作台状态和模拟/真实账户的只读快照。指定文档页和记忆文件可按原有规则读取。

**验收：** 不能通过工具参数切换 owner；跨 owner 查询失败；原始历史会话与受限 `sessions/*.summary.md` 不泄露；富途只读账户需本机主 owner 和可用 OpenD；账户未连接时返回状态而非零资产。

### US4：受限编辑与持仓草稿（P0）

用户可明确请求修改卡片、日历、自选、持仓快照或 wiki 文件；持仓文字/图片先生成待核对草稿，绝不自动登记。

**验收：** 默认模型侧写权限关闭；启用时具备本轮明确用户意图、可信 owner、版本/哈希乐观锁、审计和写后读取。卡片/日历使用 `expected_version`，持仓使用原快照版本，wiki 使用 `expected_sha256`。不提供任何下单或撤单工具。旧网页 review URL 在新系统中必须替换为可执行的 DSH 审核流程或返回可机读草稿；不可返回失效链接作为成功结果。

### US5：提供 Skills 与扩展 MCP（P1）

随包 finfreedom Skill 自动出现在 DSH 中；用户可以在 DSH 中另行安装 Skill 和经批准的第三方 MCP 连接，保持元数据、所需工具声明和权限边界。

**验收：** Skill 名称冲突有确定策略；不安全 ZIP/路径/符号链接拒绝；脚本不因安装自动运行；MCP 配置不记录或回显密钥；第三方 MCP 只读工具默认开放，写工具需独立确认与标记。

### US6：空库安装与独立运行（P0）

用户在没有 Docker 的宿主机或全新容器中安装后，可从空库开始采集市场信息并产生新的个人资料；停止旧 Financial Freedom 服务不会影响新插件。

**验收：** 本机安装不要求 Docker/MySQL 服务；首次启动自动建库并验证 schema；重启后保留新数据；空库资源返回明确缺口；版本升级可备份和回滚；旧进程关闭后不能因 import 旧模块失败。

### US7：在工作台或 DSH 中配置业务数据库（P0）

用户默认使用 SQLite。需要外部数据库时，可在 DSH 工作台的 finfreedom 数据库设置中选择 MySQL 兼容连接，填写主机、端口、库名、用户名、密码及 TLS 选项，先测试再启用。用户也可向 DSH 描述不含密码的数据库地址和部署方式，由 finfreedom 配置助手生成待填写的连接草稿并打开同一安全表单；若用户要求由 Docker 启动数据库，DSH 可按可选部署流程准备并启动数据库服务，再使用相同的连接配置流程。

**验收：** SQLite 开箱可用；外部数据库通过连接测试、权限检查和 schema 检查后才切换；失败时保留当前可用连接并给出脱敏诊断。密码不进入普通对话、模型上下文、MCP 结果、profile 明文或日志。工作台与对话草稿走相同验证器。重启后连接选择生效。切换连接不自动复制或删除数据，指向空库即显示空数据，原库保留；界面在启用前明确提示该行为。可选 Docker 启动流程幂等、使用持久卷且缺少 Docker 时提供明确替代路径。没有 Docker 的宿主机可连接已有数据库，也可一直使用 SQLite。

### US8：在 DSH 中使用 finfreedom 工作台（P0）

安装后用户能在 DSH 左侧找到持仓、自选和市场等高频入口，并在更多工具中找到指数、新闻、基金、资金、板块、日历、研究、资料、账户和设置等原工作台页面。页面保留原项目的数据语义、交互与来源时点，并适配 DSH 的布局和主题；导航时保留当前对话。

**验收：** 原页面逐项建立映射并实现适用的列表、详情、筛选和受限编辑流程；页面与 MCP 使用相同业务数据，不依赖旧 Web/DeerFlow 进程。空数据、上游不可用和权限不足须区分显示；数据库连接与凭据管理符合 US7。仅有导航入口或占位提示不能视为页面迁移完成。

## 跨场景约束

- 首批支持中文问题与说明；原始来源名称、代码和证券标识保持原样。
- DSH 负责 Agent 循环、模型路由、对话、图像理解和 Skills/MCP 调度；finfreedom 不自建 Agent、不单独发起 LLM/视觉模型请求。需要视觉理解时使用 DSH 会话附图与已声明支持 image 的模型。finfreedom 继续负责金融数据查询、确定性研究计算、业务校验、受限写入和持仓导入草稿。
- DSH 当前模型不支持图片时，必须提示用户切换到已声明支持 image 的模型，或将识别文字手动粘贴；不能把图片静默忽略，也不能由 finfreedom 回退到 DeerFlow 或隐式调用另一模型。
- 所有工具参数使用结构化 schema 校验，限制日期范围、批次、分页、输出体积、超时和并发；未知资源或工具返回明确错误。
- 市场、基金、黄金和券商数据按资产类别保留不同单位与延迟语义；不跨币种隐式求和。
- 插件版本、finfreedom 数据 schema 版本、DSH 兼容版本可查询；本地实测 DSH 为 `0.1.1-rc.2`，公开上游文档版本更新，实施须验证当前安装版本 API。
- 数据库配置是宿主管理操作，不能通过 `mcp__finfreedom__write` 或模型可调用的任意 SQL/连接修改工具直接执行；对话助手只能处理非秘密连接草稿，最终启用必须由可信用户操作触发。

## 完成判定

1. 能力盘点每一行有实现入口、数据来源、契约测试与结果；没有“待实现”却仍在 catalog 宣称可用的条目。
2. 干净安装、现有 profile 安装、Docker 重建、升级、卸载、SQLite 与 MySQL 兼容连接、连接切换、空数据、新数据持久化、上游故障、跨 owner、写入冲突和旧服务停机均有通过的验证记录。
3. 新仓库运行与打包依赖清单中无 DeerFlow、旧 Financial Freedom 源码路径或旧网页进程。
4. MCP 与 DSH 对同一输入返回等价结果；差异仅限传输包装和明确记录的兼容版本。
