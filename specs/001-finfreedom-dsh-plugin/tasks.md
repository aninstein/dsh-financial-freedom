# Feature 001 任务清单

任务按依赖顺序排列。`[ ]` 表示未开始；实施时把每个完成项关联到代码、契约测试和验证记录。任务编号保持稳定。

## 阶段 A：基线与探针

- [ ] T001 固定源工作区快照：记录 HEAD、未提交文件差异、`catalog` JSON、五个 MCP 工具 schema、25 个研究工具 schema、所有 Skills/MCP 公开元数据；不得导出凭据。
- [ ] T002 生成逐项实现矩阵：36 read、25 research、5 write、1 草稿工作流；标记源文件、数据表、外部提供方、owner 范围和运行依赖。
- [ ] T003 建立隔离 DSH profile，在本机 `0.1.1-rc.2` 和发布目标版验证 bundle patch、stdio MCP、Skill 注册、安装/卸载、工具权限钩子、工作台插件配置页与凭据服务；保存探针输出。
- [ ] T004 验证 Python/Node 打包、finfreedom SQLite/MySQL 兼容适配器和 npm/link/Git 安装路径解析；验证自动安装或显式 setup 体验及 DSH 版本兼容；更新 `research.md` 的未决项。

## 阶段 B：finfreedom 核心与数据

- [ ] T005 建立独立 finfreedom 包、配置、日志、结构化错误和 CLI；运行依赖图不含旧 `financial-freedom`、`app.main`、`deerflow_*`。
- [ ] T006 实现可信本机 owner 绑定、只读默认策略、服务端写门控和审计；覆盖跨 owner、同进程多用户与敏感输出反例。
- [ ] T007 建立统一 finfreedom 业务存储接口与 SQLite/MySQL 兼容 schema、迁移、事务、索引；实现 SQLite WAL/busy timeout/在线备份、MySQL 一致性备份、文件目录和恢复；提供默认 SQLite 自动建库、空库状态。
- [ ] T008 实现市场标的、行情、日线、日历、指数、提供方状态与公共源适配器；检查来源时间、单位、新鲜度和失效缓存。
- [ ] T009 实现新闻、央行流动性、板块、资金和基金目录/净值/披露采集；逐源限流与错误隔离。
- [ ] T010 实现上传文档目录、逐页阅读、关键词检索、研究记录、证据及回测只读查询。
- [ ] T011 实现持仓、工作台、投资记忆、wiki、本地模拟与可选富途只读查询；owner/模式隔离。
- [ ] T012 抽取并运行 25 个公开研究工具，确定性计算和 evidence 保持等价；`get_account_snapshot` 不公开。
- [ ] T013 实现卡片、日历、自选、持仓、wiki 的受限写入和版本冲突；通过 DSH Agent 视觉输入实现持仓截图识别，并由 finfreedom 校验、生成草稿和等待用户核对。

## 阶段 C：MCP/DSH/Skills

- [ ] T014 实现标准 finfreedom MCP server 五个入口和版本化契约；MCP 单独启动可调用。
- [ ] T015 实现 DSH bundle 的 patch、依赖声明、MCP 自动挂载与诊断；实际调用五个 finfreedom 工具。
- [ ] T016 内置 `finfreedom-*` Skills，规定何时查询 catalog、如何引用证据、如何区分基金披露/资金/报价和如何处理写操作；通过 Skill 注册表按需加载。
- [ ] T028 把 DeerFlow Agent/LLM/视觉调用全部替换为 DSH 内部 Agent 与模型路由；验证视觉附件在 image-capable 模型中可读，文本模型收到明确切换提示，finfreedom 运行时不再配置或调用独立模型。
- [ ] T017 实现随包 Skill 参考文件读取、安全检查、冲突处理和 DSH 后续 Skill 安装指引；不读取旧私有目录。
- [ ] T018 实现 DSH 第三方 MCP 新连接配置与逐连接权限复核；密钥仅私有存放，不在日志/模型中显示。
- [ ] T019 实现无 Docker 的本机安装及所有现有 profile 的升级、卸载、doctor，逐 profile 输出真实挂载；新增 profile 可重复安装。
- [ ] T025 实现 DSH 工作台 finfreedom 数据库安全表单，兼容目标版本的配置扩展点；默认 SQLite 与外部 MySQL 兼容连接共用 `status/prepare/test/apply/reset` 管理服务；配置留在业务库外，密码只进凭据层。
- [ ] T026 实现 DSH 对话的非秘密连接草稿与设置页引导；验证普通对话、命令、MCP 输出、profile、日志和导出不泄露密码；切换失败保留旧连接，切换成功不迁移或删除数据。
- [ ] T027 实现用户要求时的可选 Docker 数据库准备流程：预检、版本化 Compose、私有凭据、持久卷、健康检查、幂等重跑与连接草稿；无 Docker 时返回 SQLite/外部库路径。
- [ ] T029 对照原项目逐页建立 DSH 工作台页面及操作映射，区分可复用组件、数据依赖和明确排除的 Agent/交易执行流程。
- [ ] T030 实现 DSH 原生客户端扩展：高频入口、更多工具导航、主题与窗口布局适配，保留会话和键盘导航；为目标 DSH 版本提供兼容性检查与回退。
- [ ] T031 迁移原项目各页面的列表、详情、筛选和受限编辑流程，对接独立 finfreedom 业务服务；逐页覆盖加载、空数据、错误、来源和权限状态。
- [ ] T032 安装到干净 DSH Web profile 后，逐页验证布局、实际数据、交互、窄屏、主题和返回原会话；占位页面不得记为完成。

## 阶段 D：Docker 与验收

- [ ] T020 提供 Dockerfile/Compose，固定 DSH/插件/Python 依赖版本，挂载 DSH home 与 finfreedom 数据卷；默认 SQLite、可选数据库容器和外部 DB 连接；验证健康检查、空卷首次启动、重建后的新数据持久化。
- [ ] T021 对照源工作区运行逐项契约测试：能力清单每项具有正常、空数据、错误和边界样例；记录获批的差异。
- [ ] T022 关闭旧 Financial Freedom/DeerFlow 进程，用干净 DSH profile 验证市场、新产生的个人数据、Skills 与 MCP 全链路。
- [ ] T023 验证故障：上游超时/限流、富途未连接、DB 不可用、连接切换失败/schema 不兼容、数据卷只读/缺失、并发写冲突、跨 owner、路径注入、重复安装。
- [ ] T024 发布中文本机安装、Docker 部署、备份/回滚、故障排查、许可与兼容矩阵；完成验收矩阵并标注不可用的可选源。

## 并行边界

T008–T011 的数据域可在 T005–T007 完成后独立实现；T012 依赖这些域的稳定契约。T014 可在核心路由完成后开始；T015–T019、T025–T026、T028 依赖 T003 的 DSH 探针；T027 还依赖 T020 的 Compose 模板。T020–T024、T028 为集成门槛，不能仅以单元测试代替。
